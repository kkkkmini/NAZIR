# NAZIR 디자인 — Phase 1 IA 초안

> 작성: 2026-11-16 · 디자인 세션 · 상태: **초안(사용자 검토 대기)**
> 기준: `main` 개발 문서 v1.2, `docs/design/00_STATUS.md`
> 범위: 페이지 구조와 목적만 다룬다. 레이아웃·시각 디자인은 다루지 않는다.
> 표기: **[P1]** Phase 1 필수 · **[P2+]** 후속 단계 · **[결정]** 사용자 결정 필요 · **[API 없음]** 문서상 API가 없어 개발 협의 필요

## 1. 영역 분리

| 영역 | 사용자 | 진입 | 인증 | 권장 위치 |
|---|---|---|---|---|
| A. 관객 사이트 | 관객(비회원) | 공개 | 필요한 단계에서만 본인인증 | `/` 이하 |
| B. 운영 콘솔 | 기획팀(SUPER_ADMIN, STAFF) | 비공개 | 관리자 로그인 | `/admin` 이하 |
| C. 현장 입장 | 현장 스태프 | 비공개 | 관리자 로그인 또는 별도 역할 **[결정]** | `/admin/entry` (B의 하위 모드) |

**권장: 하나의 사이트에서 경로로 분리하고, B와 C는 같은 콘솔 안에서 권한으로 나눈다.**
- 근거: 현재 쿠키 설계(`__Host-nz_admin`, Path=/)와 서버 권한 검사가 한 앱을 전제로 한다. 별도 도메인은 개발 구조 변경이 필요하다.
- 관객 사이트에는 콘솔 링크를 두지 않는다. 콘솔은 검색엔진 수집을 막는다.
- C는 Phase 1에 API가 없다(QR·입장 처리는 Phase 3). Phase 1 현장 확인 방식은 **[결정]** U3.

## 3. 관객 사이트 (A)

### 3.1 페이지별 목적과 행동

| ID | 페이지 | 핵심 목적 | 주요 행동 | 접근 조건 | 데이터 |
|---|---|---|---|---|---|
| A1 | 홈 | 판매 중인 공연으로 안내 | 공연 상세로 이동, 예매 확인 | 공개 | `GET /shows` |
| A2 | 공연 상세 | 작품을 이해하고 예매를 시작 | 예매 시작, 회차 확인, 정책 확인 | 공개 | `GET /shows/{id}`, `/sessions` |
| A3-1 | 회차 선택 | 볼 날짜·시간 결정 | 회차 선택, 상세로 돌아가기 | 공개 | `/sessions` |
| A3-2 | 본인인증 | 예매 자격 확보(D-004) | 인증 시작 → 외부 → 복귀 | 공개 → BOOKING 세션 발급 | `/identity-verifications` |
| A3-3 | 좌석 선택 | 좌석 확정(최대 4석) | 좌석 선택·해제, 다음 | BOOKING | `/seats`, `/my-quota` |
| A3-4 | 주문 확인·결제수단 | 금액·좌석 확인 후 결제 | 결제수단 선택, 이메일 입력(선택), 결제, **취소하고 다시 고르기** | BOOKING + 주문 PENDING | `/orders/{id}`, `/payment-methods` |
| A3-5 | 결제 결과 | 결과를 정확히 알림 | 완료 → 확인서 / 확인 중 → 대기 / 실패 → 재시도 또는 처음부터 | 주문 접근 | `/payments/{id}` 상태 조회 |
| A4-1 | 조회 인증 | 내 예매에 접근 | 인증 시작 | 공개 → LOOKUP 세션 | `purpose=LOOKUP` |
| A4-2 | 내 예매 목록 | 내 예매 찾기 | 상세 열기 | BOOKING 또는 LOOKUP | `GET /orders` |
| A4-3 | 예매 상세·확인서 | 입장에 필요한 정보 확인 | 확인서 보기, 결제 전이면 결제 계속·취소, 결제 후 취소·환불은 **문의** | 주문 접근 | `/orders/{id}`, `/confirmation` |
| A5 | 안내·정책 | 법정·심사 고지, 문의 방법 | 읽기 | 공개 | 정적 |

### 3.2 관객 상태별 결과 화면 (A3-5, A4-3에서 공통 사용)

| 주문 상태 | 관객에게 보여줄 의미 | 다음 행동 |
|---|---|---|
| PENDING | 결제 전, 좌석 유지 중 | 결제 계속 / 취소 |
| PAYMENT_CONFIRMING · PAYMENT_UNKNOWN | 결제 결과 확인 중, 좌석 보호 중, 재결제 불가 | 기다리기, 나중에 예매 확인에서 보기 |
| REVIEW_REQUIRED | 확인이 필요해 운영팀이 처리 중 | 문의 안내 |
| PAID | 예매 완료 | 확인서 보기 |
| EXPIRED · CANCELED | 예매가 성립하지 않음 | 처음부터 다시 예매 |
| UNFULFILLED | 결제는 되었으나 발권되지 않음, 환불 진행 | 문의 안내 |
| REFUNDED | 환불 완료 | — |

### 3.3 공통 영역

- **사이트 헤더:** 로고(홈), 예매 확인(A4). 공연 목록 메뉴는 D2에 따름.
- **사이트 푸터:** 이용약관, 개인정보처리방침, 취소·환불 규정, 고객센터, 사업자 정보.
- **예매 단계 헤더(A3 전용):** 현재 단계, 선택한 공연·회차 요약, 좌석 점유 후 남은 시간(서버 기준), 예매 중단(나가기). 사이트 메뉴는 최소화.
- **인증 세션 표시:** 인증된 상태(마스킹된 이름)와 세션 남은 시간, 인증 종료.

### 4.2 공통 영역

- 상단: 현재 관리자·역할, 로그아웃, 세션 만료 안내(유휴 30분 권장).
- 좌측 메뉴: 위 상위 메뉴. 확인 필요 사안·연동 실패에 미해결 개수 표시.
- 검색: 주문번호·티켓번호 기준. 전화번호는 기본 마스킹(원문 열람은 별도 권한).
- 모든 변경 action은 사유 입력과 확인 단계를 거치고 감사 로그에 남는다.
